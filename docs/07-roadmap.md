# Multa — Roadmap (веб-first)

**Решение основателя (2026-07-19): dogfooding-first.** Продукт строится в первую очередь для себя — основатель и есть первый пользователь и валидация. Следствия:
- Главный DoD MVP: **основатель закрывает свою Excel-таблицу и ведет следующий период выплат целиком в Multa.** Всё, что для этого не нужно, — не MVP.
- Стальной сердечник MVP: онбординг → план периода → цифра дня → раскладка с подтверждениями → текстовый ввод → **чеки (QR-путь + vision-фоллбек через OpenAI)** → сигнал burn-rate → пересборка → размен с фактическим курсом. Голос, импорты, аудит категорий — после переезда с таблицы.
- Спринт 0 (интервью/консьерж) — не гейт, а параллельный фон: боли других людей соберутся из живого использования и первых «подтянувшихся».
- Спринт 7 (биллинг, админка, тарифы) — отложен до появления сторонних пользователей. Тарифные решения не принимаются сейчас вовсе.
- Мини-бот «ввод + цифра дня» — часть MVP (основатель живет в Telegram), полный бот из 05-bot-ux — потом.

**Решение основателя (2026-07-30): сначала внутряк, потом интерфейс.** Текущий UI признан негодным (крупный, неинформативный) и будет переработан целиком в Спринте 6 (issue #30). До тех пор новые фичи выводятся на существующие экраны плотно и без нового визуального языка — цель не красота, а чтобы основатель мог начать вести бюджет до редизайна. Дизайн-ресерч (этап 0 в #30) идёт параллельно спринтам 3–5, чтобы к переработке прийти с готовыми решениями, а не с нуля.

Каждый спринт заканчивается работающим инкрементом. Оценки — в «сессиях вайбкода» (1 сессия ≈ вечер работы с Claude).

## Спринт 0 — Валидация до кода (параллельно спринтам 1–2, по Lean Startup)
- 5–7 интервью с релокантами из чатов (Белград/Тбилиси/Ереван): как ведут бюджет, что с разменом, где ломаются.
- Консьерж-MVP: вести 2–3 человек по нашей механике руками (таблица + сообщения) 2 периода. Проверяем: понятна ли «цифра дня», пользуются ли пересборкой, реален ли ага-момент.
- Критерии фальсификации: если консьерж-юзеры не спрашивают «цифру дня» сами к концу 2-го периода — гипотеза ядра под вопросом, останавливаемся и думаем.
- Старт канала «строю Multa» (по Райту: доверие копится ~3 месяца — ровно срок разработки MVP) + бесплатный калькулятор размена как lead magnet.

## Спринт 1 — Фундамент (3–4 сессии)
- Монорепо, CI (typecheck + vitest), docker-compose (postgres + api + caddy), Drizzle-миграции по 02-data-schema, better-auth.
- packages/core: money, periods, cascade + полные юниты (инварианты из 01-domain-model §Инварианты).
- Auth (magic link + Google), создание workspace, онбординг шаги 1–2.
- FX-пайплайн: cron ЦБ+Frankfurter, getRate с фоллбеками, тесты на выходные/кроссы.
- DoD: юзер регистрируется, задает валюту, ритм планирования и источники дохода, видит пустой план периода; курс любой пары на любую дату достается корректно.

## Спринт 2 — План и каскад (3–4 сессии)
- Долги, конверты, цели, валютные корзины: CRUD + онбординг шаги 3–4.
- Автосборка плана периода каскадом; дашборд: герой-цифра, категории, блок «К размену».
- Recurring items → автозаполнение следующего периода. _(сделано в Спринте 5, issue #21: платежи вне обязательств питают прогноз)_
- DoD: онбординг до ага-момента < 2 минут; план на два периода вперед собирается сам.

## Спринт 3 — Факт и размен ✅ (сделано 2026-07-30)
- Ввод: умное поле (regex-парсер), быстрые кнопки, «крупный мазок».
- Факт прихода: разовый доход «пришло сегодня» (side hustle) — транзакция дохода, а не правка источника.
- Раскладка дня выплаты: подтверждение плановых пунктов (внесено / не внесено / частично).
- ExchangeOp: «размен сделан» → фактический курс, спред; экран «Размен» с историей.
- Привязка транзакций к периодам, план/факт на дашборде.
- DoD: полный цикл «план → факт → остаток по категории» живет; спред считается.

## Спринт 4 — Сигналы и пересборка ✅ (сделано 2026-07-30) ← сердце продукта
- burnRate + SignalBanner; модал пересборки с каскадом-наоборот.
- PlanRevision: история, ранжирование предложений по прошлым решениям, «как обычно»-бейдж.
- Обучение плана: «ты 3 периода подряд тратишь на еду 24k при плане 20k — поднять?»
- Прогноз-таймлайн: recurring + долги с датами закрытия + риски целей.
- DoD: сценарий «18-го кончилась еда» решается за 2 клика; система предлагает то, что юзер выбирал раньше.

## Спринт 5 — Чеки и AI ✅ (сделано 2026-07-30; остаток — голос через Whisper)
- QR: jsQR на клиенте, ФНС РФ + suf.purs.gov.rs парсеры; ревью-экран позиций.
- Vision-фоллбек (Gemini Flash/Haiku, structured output), confidence → «Общее».
- LLM-фоллбек текстового парсера, голос (Whisper).
- DoD: чек из Максija раскладывается по статьям за <10 сек; плохой чек падает в «Общее» одним тапом.

## Спринт 6 — Переработка интерфейса, полировка и закрытая бета (3–4 сессии)
- **Полная переработка веб-интерфейса (issue #30).** Решение основателя 2026-07-30: текущий UI крупный и неинформативный, «дешёвая поделка». Целевой дашборд — bento-обзор: динамика трат, приходы, предстоящие платежи со статусом «внесено / не внесено», быстрые действия (трата, разовый приход, чек). Начинается с ресерча приложений и баз дизайна, затем новый визуальный язык, затем экраны. Ресерч можно вести параллельно спринтам 3–5 — он не блокирует код.
- PWA (офлайн-очередь), экспорт CSV, удаление аккаунта, EN-вычитка, Sentry.
- Онбординг-полировка, пустые состояния, лендинг.
- 10–20 пользователей из чатов релокантов, метрики: онбординг-завершение, D7, принятые пересборки.

## Спринт 7 — Взрослый контур (3–4 сессии; ЗАПУСКАЕТСЯ только после сигнала retention: 10+ бета-юзеров живут 3+ периода)
- Админка v1: поиск workspaces, comp-подписки, метрики, здоровье fx, audit_log.
- Биллинг: plans/entitlements-middleware, Stripe (подписка+вебхуки+возвраты), триал 14 дней, деградация в Free без потери данных.
- Правовые страницы (terms/privacy/cookies/subprocessors) + версии и акцепты; экспорт и удаление аккаунта до конца.
- Транзакционные письма (Resend/Postmark), rate limiting, Uptime Kuma, staging + CI/CD, события продуктовой аналитики.
- DoD: незнакомый человек может зарегистрироваться, оплатить, отменить, вернуть деньги и удалить аккаунт — без участия основателя.

## Фаза 2 — Бот (после беты)
grammY + webhook, Telegram Login, ввод/дайджесты/сигналы по 05-bot-ux, Mini App поверх веб-кода.
Плюс импорт банковских выгрузок (CSV/XLSX): маппинг колонок с шаблонами банков, дедуп, сверка полноты, калибровка плана по медианам (01-domain §ImportBatch).

## Фаза 3 — Монетизация и рост
Stripe + Telegram Stars, Free/Pro-границы, региональные цены; Product Hunt, SEO-сравнялки, реферальный месяц Pro.

## KPI продукта
- Активация: % дошедших до ага-момента онбординга.
- Живучесть: % юзеров, вносящих факт ≥3 периодов подряд (главная метрика — победа над «смертью трекера»).
- Полезность мозга: % принятых предложений пересборки.
- Валютное ядро: % юзеров с ≥1 разменом в периоде.
