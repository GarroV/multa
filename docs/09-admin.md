# Multa — Админка

Отдельное приложение `apps/admin` (тот же стек, что web), доступ: отдельный поддомен за Caddy + basic-allowlist по IP (или Cloudflare Access), вход только для users из `admin_users`, обязательный TOTP (2FA). Роли: `owner` (всё), `admin` (без управления админами), `support` (только просмотр + выдача comp-подписок).

## Разделы

### Workspaces / пользователи
- Поиск по email/tg/id; карточка: план, статус подписки, дата регистрации, активность (последний факт, число периодов подряд), число валют/счетов, AI-usage.
- **Приватность по умолчанию: транзакции, суммы и заметки пользователя админу НЕ видны.** Виден только метаслой (счетчики, статусы). Диагностический доступ к данным — через явный «support-режим»: запрашивается согласие пользователя (кнопка в его настройках/письмо), доступ на 48ч, каждая операция — в audit_log. Это и этика, и аргумент доверия.
- Действия: заблокировать (abuse), разблокировать, форс-logout, удалить по запросу пользователя (GDPR), запустить экспорт данных.

### Подписки и планы
- Выдать/продлить/отменить подписку вручную (comp: бета-тестеры, инфлюенсеры), причина обязательна → audit_log.
- Редактор планов и цен (plans/plan_prices): entitlements, PPP-корзины, активация/архив плана. Изменение плана не трогает активные подписки до продления.
- Платежи: список, поиск по external_id, инициировать возврат (Stripe), пометить disputed.

### Метрики (дашборд)
- Регистрации, активация (дошли до ага-момента), D7/D30, «живучесть» (3+ периода подряд с фактами), % принятых пересборок, % юзеров с разменом.
- Деньги: MRR, конверсия Free→Pro, churn, возвраты.
- Затраты: AI-расход по дням ($, по моделям), топ-workspace по AI-usage (ловить аномалии).

### Эксплуатация
- Feature flags: включение фич по workspace/проценту (постепенные раскатки).
- Здоровье fx-пайплайна: последняя успешная загрузка по источникам, дырки в fx_rates, кнопка «дотянуть вручную».
- Очередь ошибок распознавания чеков (failed receipts) — для улучшения промптов.
- Аудит-лог: все действия админов, фильтры по актору/объекту. Неизменяемый (append-only).
- Объявления: баннер в приложение / письмо сегменту (maintenance, новые фичи).

## Техника

- `admin_users`, `audit_log`, `feature_flags` — см. 02-data-schema §Admin.
- Админ-API — тот же apps/api, отдельный префикс `/admin/*` с отдельным middleware (роль + 2FA-сессия); ни один обычный эндпоинт не отдает чужие данные даже админу.
- Каждый мутирующий админ-хендлер пишет audit_log в той же транзакции.
- MVP-версия админки (спринт 7): workspaces-поиск + comp-подписки + метрики + fx-здоровье. Остальное — по мере надобности.
