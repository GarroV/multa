# Multa — критическая проходка (2026-07-19)

Честный взгляд на проект после полного цикла проектирования. Сверено с рынком и опенсорсом.

## Сверка с GitHub / опенсорсом

- **Firefly III** (~24k звезд, активен) — ближайший функциональный сосед: полноценная мультивалютность, rules-engine автокатегоризации, API, self-hosted, бесплатен. НО: это бухгалтерия (двойная запись), не planning-first; нет периодов по выплатам, каскада, размена, «цифры дня», бота; UX для гиков. Вывод: не конкурент за нашу ЦА, но заберет всех technical self-hosters — не воевать за них.
- **Actual Budget** (~27k звезд) — envelope-бюджет с отличным UX, но мультивалютность слабая (по сути одна валюта на бюджет). Подтверждает: даже сильнейший опенсорс не решает нашу задачу.
- Отдельные элементы нашей связки уже перестали быть уникальными: pay-period-бюджет есть (Salary Cycle, Koody), envelope+multicurrency есть (Tallyroot). **Полная связка (периоды выплат + валютные корзины/размен + каскад + бот + без записи покупок) по-прежнему не собрана ни у кого** — но окно не пустое и сужается.

## Сильные стороны

1. Ниша реальна и растет; основатель = целевой пользователь с 2-летней историей данных (таблица) — глубина понимания боли, которой нет у конкурентов.
2. Уникальная связка механик с подтвержденным «секретом» (планирование мазками против учета трансакций).
3. Независимость от банковских API = глобальность с первого дня, включая рынки, куда Plaid-игроки не придут.
4. Почти нулевая стоимость эксплуатации (self-hosted, QR-чеки бесплатны, AI — копейки).
5. Дистрибуция через живые русскоязычные комьюнити + контент-подход Райта; аудитория уже в Telegram.
6. Документация как актив: проект может строить любой исполнитель без потери замысла.

## Слабые стороны (и что делать)

1. **Ресурсный разрыв — главный риск.** Соло, 2–3 ч/день, при этом roadmap ~25+ сессий до беты, плюс треки А (заказы) и Folio. Митигация: жесткий MoSCoW-срез MVP (ниже) + решение о месте Multa в личной стратегии после Спринта 0.
2. **Домен уже перегружен для MVP.** За один день проектирования добавлены: подтверждения, защищенные категории, категорийный аудит, импорты, отчеты, голос с позициями. Всё правильно — но если строить сразу всё, бета не случится. Стальной сердечник MVP: онбординг → план периода → цифра дня → раскладка с подтверждениями → текстовый ввод → сигнал burn-rate → пересборка. Чеки, голос, импорты, аудит категорий — ПОСЛЕ первых живых пользователей.
3. **Противоречие «веб-first vs ЦА в Telegram».** Решение веб-first понятно (ядро, workspace), но аудитория живет в TG и вход к ней — через чаты. Бот в фазе 2 удлиняет путь к дистрибуции. Компромисс: в MVP-веб добавить простейшего бота-«ввод+цифра дня» (200 строк) раньше полного бота из 05-bot-ux.
4. **Free/Pro граница спорна.** «Free = 2 валюты» бьет по ядру ниши: наш типовой юзер (RUB+RSD+EUR) мультивалютен по определению — Free для него бесполезен, это злит, а не конвертирует. Честнее: валюты не резать вообще; Pro = прогноз >2 периодов, AI-лимиты, отчеты (годовой/партнерский), импорты, API. Требует решения основателя.
5. **Юрисдикция не решена — блокер монетизации.** Stripe недоступен РФ-юрлицам; у основателя опция фирмы в Сербии. Решить до спринта 7, иначе биллинг проектируется в вакууме.
6. **Домашний сервер для прода** — ок для беты, но с первым платящим пользователем нужны SLA и георезерв: Hetzner VPS (€5–10) с тем же docker-compose. Прописано как план Б — сделать планом А для прода.
7. **Ров тонкий на старте.** PlanRevision-память становится switching-cost через месяцы использования, а связку механик могут скопировать Tallyroot/Lunch Money быстрее, чем мы наберем базу. Митигация: скорость в узкой нише + комьюнити + бренд, не патенты.
8. Название Multa («штраф» на романских языках) — решено бренд-игрой, но остается риском при глобальном масштабировании; переоценка перед EN-запуском.

## Угрозы

- Tallyroot/Lunch Money добавляют планировщик размена (это одна фича для них).
- TG-боты (Cointry и др.) дорастают до планирования.
- Ужесточение платежной изоляции РФ (Stars — единственный канал) или наоборот легализация Plaid-аналогов в регионе, обнуляющая «преимущество без банков».
- Личный: срыв регулярности (главный риск по собственной стратегии основателя).

## Возможности

- Миграция с Excel-таблиц как канал привлечения («у меня есть таблица» — теплейший сегмент).
- Налоговый экспорт для фрилансеров-мультивалютников — клин, за который платят отдельно.
- Комьюнити-данные (курсы обменников по городам) — сетевой эффект, недоступный глобальным игрокам.
- B2B2C позже: релокационные агентства, работодатели распределенных команд.

## Топ-5 действий по итогам проходки

1. Спринт 0 — обязательный гейт: не начинать спринт 3+, пока нет 5 интервью и консьерж-вердикта по H1–H3.
2. Ужать MVP до стального сердечника (см. §Слабые-2); остальное перенести в пост-бету.
3. Пересмотреть Free/Pro: валюты не ограничивать, монетизировать прогноз/AI/отчеты.
4. Решить юрисдикцию (Сербия?) до проектирования биллинга в коде.
5. Мини-бот «ввод + цифра дня» включить в MVP-срез, не откладывая в фазу 2.
